# 信号检测论（SDT）交互式实验室

一个纯静态的教学网站：用四个"角色扮演"式的判断任务，亲手体验**信号检测论**的核心概念——为什么单看「准确率」不够，以及**敏感性 d′** 与**判定标准 c** 是如何被区分开的。

四个角色：

| 角色 | 任务 | 需要判断的"信号" | 侧重考察的难点 |
| --- | --- | --- | --- |
| 🍄 采蘑菇 | 山野采集 | 这朵菇**有毒**还是**无毒** | **漏报的代价特别大**（吃错会中毒）→ 最优标准应该很宽松 |
| 🏺 鉴假员 | 拍卖行预展 | 这件器物是**真品**还是**赝品** | **虚报的代价特别大**（把真品当赝品，一锤砸碎）→ 最优标准应该偏谨慎 |
| 🐦 观鸟 | 林间样线调查 | 看到的是**鸟**还是**树叶** | **两种错的代价都不大**（−16 / −6）→ 最优标准就压在正中间，**标准因各人而异** |
| 🧸 质检员 | 手办出厂检验 | 涂装**不合格**还是**合格** | **长期没有信号的敏感性**（不合格的只有 8%）→ 最优标准接近中立，考的是 d′ 会不会掉 |

>
> 四个场景共用一个约定：判断为「有毒 / 是鸟 / 赝品 / 不合格」= **判断为有信号**（说「有」），判断为「无毒 / 不是鸟 / 真品 / 合格」= **判断为无信号**（说「无」）。这句话写在结果页混淆矩阵的表头（"实际：有信号 / 无信号"）和概念实验室五个模块的顶部，避免同学在"H 到底是谁"上绕晕。游戏里的说明层不再重复它——按钮上就是角色自己的说法（「有毒」「赝品」…）。

## 一、如何打开

**最简单的方式：直接双击 `index.html`。**

全部依赖都是本地文件，脚本用普通 `<script>` 标签加载（不是 ES module），因此 `file://` 协议下可以正常使用，不需要联网、不需要构建步骤、不需要服务器。

如果希望通过网址访问（例如教室投影、局域网共享），任选一种：

```bash
# 方式 A：Python 自带服务器
cd sdt-lab
python -m http.server 8000      # 然后访问 http://localhost:8000

# 方式 B：Node
npx serve .
```

部署到 Railway / Vercel / Netlify / GitHub Pages 等任何静态托管也都可以，把整个目录上传即可。

## 二、页面结构

1. **登录页**：输入学号 + 姓名（也可"以游客身份进入"）。姓名学号只存在本机浏览器里。
2. **任务选择页**：四张角色卡片，每张卡上只有先验概率 P(S) 与本关侧重（"漏报的代价特别大"等）两个标签——**不再写"信号 = 「××」"**，那是点进去之后由角色自己的按钮文字（「有毒」「赝品」…）交代的。上方是四项设置：难度 d′、试次数（20 / 100）、逐试次反馈、**图片呈现时长**（1.5 / 3 / 6 秒 / 不限时）。
3. **实验页**：**先做 5 次练习，再做正式试次**。逐个试次呈现一张画面，你按「有信号 / 无信号」作答；答完立刻进入下一试次。底部有"参考图鉴"——左右两格只差在是否有信号，帮你建立判断锚点。**答完最后一个试次会自动跳到结果页**，不需要再点任何按钮。
   - **任务说明层（收得很短）**：点进一关先盖一层说明，只有四块——这一关在干什么（角色描述）、该看哪些线索（观察提示）、接下来怎么走（5 次练习 + 20 次正式判断，一句话）、快捷键（鉴假员再多一句"按赝品 = 抡锤"）。**奖惩表、"信号＝有信号"的口径句、P(S) 换算成次数、"画面只显示几秒"都已撤掉**：代价的不对称由卡片上那一句话交代，具体数字在结果页的 `c*` 说明与概念实验室的"标准与奖惩"面板里还会再出现；限时则靠画面底部的薄荷色倒计时条实时显示，不必再写一行字。

   - **练习试次（每关 5 次，不计分）**：五个练习的画面是固定的（明确的信号 → 明确的噪音 → 较明确的信号 → 较明确的噪音 → 中间地带，难度随 d′ 缩放，全班一致，方便老师统一讲解）。每答完一次，画面立刻弹出一张反馈卡，用信号检测论的正式术语告诉你这一次属于哪一类：
     - **击中**＝有信号，你说了「有」；**正确拒斥**＝无信号，你说了「无」；
     - **漏报**＝有信号，你说了「无」；**虚报**＝无信号，你说了「有」。
     卡片还会写明"你说「××」· 它其实是「××」"，以及这一次属于哪一种。状态栏也实时把四类的累计次数摆出来，让同学一边做一边把词和情形对上号。**练习不计入混淆矩阵**（正式实验仍是 20 次），练习期间给的反馈也不受"逐试次反馈"开关影响。
   - **练习结束的过渡层**：答完第 5 个练习试次后会自动停下，弹出一层提示。这一层刻意只留两句话：一句交代"刚才那 5 次是练习、**不计入成绩**，接下来还有 20 次、**这 20 次计入结果**"；一句解释为什么不再给反馈（"正式试次不会再告诉你对错——知道对错，标准就被它牵着走了"；若在选择页开了"逐试次反馈"，则换成"正式试次仍会亮 ✓ / ✗，但不再告诉你它实际是什么"）。点「开始正式实验」才继续——免得同学以为"怎么猝不及防就开始算分了"。
   - **限时呈现**：画面底部有一条薄荷色倒计时条。时间一到画面被撤下，换成一块「画面已隐藏 —— 凭刚才的印象作答」的提示板，但作答按钮仍然有效。这是"限制编码时间"的标准做法：逼同学靠记忆里的印象作答，而不是反复盯着图找细节（那会把任务变成"慢慢比对"，d′ 会被策略性抬高）。选择"不限时"则没有倒计时条。
     **倒计时从"收起任务说明层"那一刻才开始**（`Game.begin()`）：`Game.start()` 是在说明层还盖着的时候执行的，如果那时就开表，同学读说明的十几秒会把第 1 个试次的画面耗掉，等点「开始」时只剩一块"画面已隐藏"的板子——看起来就像"第一个试次没给图"。同理，两个试次之间的空白间隙（240 ms / 练习 1.5 s）不接受作答，否则连按两次键盘就会把下一个试次一起答掉。
   - **砸碎效果（仅鉴假员）**：在这一关里，按「赝品」就等于抡锤——画面会先放一段约 0.76 秒的砸碎动画（锤子抡下来、器物炸成飞散的碎片、命中处粉尘与镜头抖动），同时用 Web Audio 现场合成一声碎裂声（闷响 + 高频噪声爆 + 几记清脆的落地声，不需要任何音频文件）。碎裂声可以用状态栏右侧的 🔊 按钮静音，这个开关记在 `sdtlab.muted.v1` 里，只对鉴假员显示。
     **关键设计：砸碎效果不携带任何信息。** 无论对错、无论有没有开启"逐试次反馈"，动画和声音都完全一样；只有开了反馈时命中粉尘的颜色才会不同（暖金＝砸对了）。这样"打击感"纯粹是沉浸感，不会把答案偷偷塞回测量里。任务说明层也会把这一点明确写给同学。
4. **结果页**：你的混淆矩阵（H / M / FA / CR）+ 完整 SDT 指标（P(H)、P(FA)、d′、c、β、A′、准确率），并给出"按本场景的先验与奖惩，最优标准 c\* 应该在哪"，对照你自己的 c 给出反馈。还有"为什么光看准确率不够"的讲解（两种典型同学：稳健型 vs 冒险型，准确率相同但 d′ 与 c 完全不同）。
5. **概念实验室**：五个交互模块
   - **分布与判定标准**：拖动 d′ 和 c，看信号分布与噪音分布、判定标准的位置和四格面积变化；
   - **ROC 曲线**：拖 d′ 看 ROC 曲线形状与 AUC，并在 z-ROC 坐标下理解等方差假设；
   - **先验与奖惩**：拖 P(S) 和四种结果的收益/代价，看最优 β\* 与 c\* 怎么算出来；
   - **最大似然**：理解"似然比 β 与判定标准 c 的关系"；
   - **警觉衰退（蒙特卡洛）**：模拟 8 个时段的信号检测任务，看 d′ 随时间衰减、c 漂移。
6. **教师管理后台**：本机所有成绩的汇总——班级 ROC 散点、d′ 分布、c 分布、各场景平均 d′ 对比、经验 d′ vs 系统设定 d′、明细表；支持按游戏筛选（全部 / 采蘑菇 / 鉴假员 / 观鸟 / 质检员）、导出 CSV / 导出 JSON / 导入 JSON（合并）/ 清空。

## 三、模型与参数（教学用设定）

### 3.1 基本公式（等方差高斯）

```
H  = Φ(d′/2 − c)            FA = Φ(−d′/2 − c)
d′ = z(H) − z(FA)           c  = −[z(H) + z(FA)] / 2
β  = e^(d′·c)               A' = Pollack & Norman (1970) 非参数敏感性
AUC = Φ(d′/√2)
```

其中 `z` 是标准正态分位数，`Φ` 是标准正态累积分布函数。

**试次生成方式**：每个试次先在潜变量上抽样——信号试次 `x ~ N(d′, 1)`，噪音试次 `x ~ N(0, 1)`，然后把这个 `x` 单调地映射成渲染出来的画面。因此"理想观察者"（以 x=0 为界判断）的实际 d′ 恰好等于设定值，设定多少就是多少，不会因为美术素材而不准。屏幕上的图像（菌盖颜色/斑点数量、鸟与叶簇的渐变程度、釉面合模缝与贴花纹样的明显程度、涂装溢色与挂漆的严重程度）都是 `x` 的单调函数。

> **美术细节上的一个坑**：破绽的"起点"必须落在噪音分布的中心（`x = 0`）**之后**。噪音试次 `x ~ N(0, 1)`，画面参数 `t = (x + 3.4) / 6.8` 因而集中在 `t = 0.5` 附近——如果某条破绽在 `t = 0.5` 就已经显形，那么**大多数真品看起来也全是破绽**，任务就退化成"随手砸"。鉴假员这一关最初把合模缝设成 `smooth(t, 0.28, 0.62)`，在 `t = 0.5` 处已经有 0.71 的不透明度，于是"每一件瓷器上都有缝"。现在四条线索的起点都推到了 `t ≥ 0.48`（缝最晚、坡度最陡），常见的真品是**一条破绽都没有**的，只有嫌疑大的那几件才陆续显形。

**试次数分配**：按先验 P(S) 分配，`nS = round(n × P(S))`，其余为噪音试次，然后打乱顺序。同学事先不知道某个试次是什么。

**极端比例的修正**：当 H 或 FA 为 0 或 1 时（有限试次数很容易出现），直接取 z 会得到 ±∞。记录里保存的是 **log-linear 修正**（Hautus, 1995）后的比例：

```
H  = (击中 + 0.5) / (nS + 1)
FA = (误报 + 0.5) / (nN + 1)
```

结果页显示的混淆矩阵仍是原始的整数计数，SDT 指标用修正后的比例计算。

### 3.2 四个角色的先验与奖惩

默认难度 **d′ = 1.8**、**20 个试次**（可在任务选择页看到每张卡上的设定值）。

| 角色 | 信号 | P(S) | 击中 (H) | 漏报 (M) | 误报 (FA) | 正确拒斥 (CR) | β\* | c\* |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 🍄 采蘑菇 | 有毒菇 | 0.40 | +10 | **−100** | −8 | +10 | 0.246 | **−0.78** |
| 🏺 鉴假员 | 赝品 | 0.30 | +10 | −20 | **−40** | +5 | 3.500 | **+0.70** |
| 🐦 观鸟 | 是鸟 | 0.30 | +12 | −16 | −6 | +6 | 1.000 | **0.00** |
| 🧸 质检员 | 涂装不合格 | **0.08** | +15 | **−50** | −4 | +2 | 1.062 | **+0.03** |

最优标准由下式算出：

```
β* = [P(N)/P(S)] × [(V(CR) + C(FA)) / (V(H) + C(M))]
c* = ln(β*) / d′
```

四个场景刻意排成一条刻度——**两个极端 + 两个中立**，方便课堂对比：

- **采蘑菇（漏报代价极大）**：吃错蘑菇会中毒（漏报代价 100 远大于其他）→ 最优标准非常**宽松**（c\* = −0.78），宁可错采也不能漏采。注意 d′ 相同的人，只要 c 不同，准确率可能差很多。
- **鉴假员（虚报代价极大）**：预展上一锤子下去，一件真品就没了——赔偿金、官司、名声，没有一样补得回来（误报代价 40）；而放走一件赝品，无非是交一笔学费（漏报代价 20）。所以最优标准偏**谨慎**（c\* = +0.70，四个场景里最严），要有足够证据才抡锤。**它和采蘑菇是同一种东西的两个极端**：同样是"眼前这团东西到底是不是目标"，采蘑菇那边漏报贵（−100），标准压到 −0.78；这一关虚报贵（−40），标准就翻到 +0.70——而两关的 d′ 一个字符都没变。这两关连着做，奖励不对称如何把 β\* 推走就一目了然。
- **观鸟（两种错的代价都不大）**：漏掉一只真鸟 −16，把树叶误记成鸟 −6，**两个数字都小、也差得不多**。于是最优标准落在了**正中间（c\* = 0.00）**。有意思的是它是被两股力量**抵消**出来的：先验偏低（只有 30% 是鸟）本来会推着你谨慎一点，而漏报比虚报贵又把你往宽松那头拉，两下刚好扯平。所以这一关**没有"标准答案"**——多记一笔或少记一笔都不吃亏，你的 c 就纯由你自己的偏好决定。放在两个极端关中间，它正好是一个"零点参照"：同学会看到同一批人在这里的 c 分得最散，**不是因为他们更会做，而是因为这里没有规范压力**。
- **质检员（长期无信号的敏感性）**：产线工艺很成熟，不合格的**只有 8%**——每 100 只里大约 8 只，20 个试次里通常只有 1至2 次真的是信号。而且本关的漏报代价（50）和误报代价（4）换算下来，最优标准几乎就在**中立位置**（c\* = +0.03）。也就是说，这一关**不考"标准放在哪"，考的是"在连续几十只都没问题之后，你还看得清吗"**：长时间的"什么都没发生"会让人不知不觉松懈，敏感性悄悄下降，d′ 掉下来。这正是警觉（vigilance）研究的核心问题，可以在「概念实验室 → 警觉模拟」里继续推演。
  信号少还有一个副作用：20 个试次里只有 1至2 个信号试次，**d′ 的抽样波动会很大**。想得到更稳的 d′，可以在选择页改用 100 次的长版（那时约有 8 次信号）。**注意误报与正确拒斥的代价被压到了 −4 / +2**：先验低到 8% 之后，(1−P(S))/P(S) = 11.5 倍的力量全压在"谨慎"那头，只有把误报的代价调小，才能让 β\* 落回 1 附近——否则算出来的是"偏谨慎"（c\* ≈ +0.46），这一关就不再是"标准已定、请守住敏感性"了。

> **观鸟和质检员的 c\* 都在 0 附近，但原因完全不同**，课堂上正好拿来对照：观鸟是"两种错的代价都小、先验与代价相互抵消"，所以标准自由；质检员是"奖惩比正好抵消了低先验"，标准**也**该放在中立——但它真正要考的不是标准，而是 d′。一个是"标准随你"，一个是"标准已定，请守住敏感性"。

结果页会拿你自己的 c 和该场景的 c\* 比，告诉你"你比最优标准更宽松/更谨慎，因为……"。

## 五、数据存储与"收集全班数据"的工作流

**本方案是纯静态的，没有服务器**，所有成绩存在**同学自己浏览器的 localStorage** 里（成绩 `sdtlab.records.v1`、登录信息 `sdtlab.user.v1`、碎裂声开关 `sdtlab.muted.v1`）。这意味着：

- 老师在自己的电脑上打开教师后台，**只能看到本机浏览器里产生的记录**，看不到其他同学电脑上的数据；
- 同一台电脑上不同浏览器（Chrome / Edge）之间数据不互通；
- 清除浏览器数据会一并清掉记录。

如果老师想汇总一个班的成绩，推荐流程：

1. 同学完成实验后，**自己**进入教师后台页面点「导出 JSON」；
2. 通过课程群 / 学习平台 / 共享文件夹把 JSON 交给老师；
3. 老师在自己的后台点「导入 JSON」，选择**多个同学的文件**依次导入即可（导入是**合并**，按记录 id 去重，不会覆盖已有数据）。

CSV 导出适合直接用 Excel 打开做进一步统计（带 UTF-8 BOM，中文不会乱码）。除混淆矩阵与 SDT 指标外，每行还记了「逐试次反馈（开启/关闭）」和「图片限时(秒)」两列，方便老师比较不同设置下收集到的数据是否可比。

如果希望**真正联网汇总**（同学一提交，老师立刻能看到全班数据），则需要加一个后端——最小改动是在 `js/store.js` 的 `add()` 里加一个 `fetch('/api/records', {method:'POST', body: …})`，并写一个几十行的存储接口。现有代码结构已经把这个点隔离在 `Store` 里了，不需要动其他文件。

## 六、无障碍 / 课堂使用提示

- **快捷键**：实验页里 `F` 或 `←` 选左侧答案，`J` 或 `→` 选右侧答案（也可以点按钮）。这样同学可以专心看图，不用来回找按钮。
- **实验页是自适应的**：画面高度按浏览器窗口高度自动计算（`--scene-h: clamp(230px, 91vh - 302px, 660px)`），保证「画面 + 参考图鉴 + 作答按钮 + 页脚」在 1280×720 及以上的窗口里**一屏放下、不用滚动**。用 91vh 而不是 100vh 是因为图鉴条和作答按钮自己也按 vh 缩放，窗口越高它们吃掉越多——线性拟合下来非画面部分 ≈ 302px + 0.09vh，剩下多少就都给画面。窗口高度 ≤800px 时另外压缩各处留白（见 `css/style.css` 末尾的 `@media (max-height: 800px)`）。游戏页外面那层 `.game-wrap` 固定 1240px 宽（不跟着画面缩），画面 / 图鉴 / 作答按钮再各自按 16:9 居中排成一列——早先整层宽度由画面高度反推，矮屏上只剩 500px 出头，标题行会被挤成两行、白白吃掉七八十像素。任务选择页在宽屏下把四项设置排成三栏（`@media (min-width: 1080px)`），让四张角色卡尽量留在首屏（卡片网格是 `repeat(auto-fit, minmax(226px, 1fr))`，窗口窄了会自动折行）。结果页 / 实验室 / 后台是内容页，正常滚动。
- 每个角色的"参考图鉴"左右两格用同一个随机种子生成，**只有信号不同**，其余细节完全一致，避免同学靠风格差异猜答案；图鉴里把目标放大、叶子减少（`GUIDE_FOCUS`），否则在那条很矮的图鉴带里小鸟只有十几像素、起不到参考作用。手办也用 `GUIDE_FOCUS` 放大到近 2 倍、并把画面抬起来只留「头 + 上身」，这样才看得清有没有溢色、挂漆。
- 结果页的反馈、概念实验室的数值都是实时计算的，可以让学生自己推导公式再对照。
- **配色是一套"炭灰底 + 薄荷点缀"的深色主题**：底色 `#2E343A`、正文 `#E9EBED`、点缀 `#73C8B8`。所有层次都由 `css/style.css` 顶部的 `:root` 变量给出（`--bg` / `--card` / `--surface` / `--accent` / `--accent-soft` / `--on-accent`…），换主题只改这一处。两处例外：canvas 图表把调色板写在 JS 里（`js/charts.js` 的 `COLORS`、`js/dashboard.js` 的 `GAME_COLOR` 与图表底色 `#333A41`），它们是为深底单独选的高饱和亮色，改主题时要一起改；游戏画面（`js/games.js` 里画蘑菇/瓷器/鸟/手办的那一堆颜色）画在本来就深色的 `#20242c` 画布上，属于"照片"内容，不随主题变。

### 6.1 四条值得记下的实现细节

- **手办是"一个整体"**：头部、脖子、上身用同一套路径连起来画，中间不留缝隙——早期版本只在头和身体之间画了颜色，看起来像"头浮在空中"。脖子用肤色多边形接到外套领口，领口再用一个椭圆封住接缝。
- **画布尺寸要在布局完成后再取**：`Game.start()` 是在页面还隐藏着的时候执行的，此时 `canvas.clientWidth` 是 0，`Charts.prep()` 只能退回 640×320 的兜底值。所以 `Game.redraw()` 里**必须同时重绘主画面和图鉴条带**——否则那块 640×320 的位图会被拉伸进细长条，图鉴里的东西横向拉宽、纵向压扁。
- **图鉴条带又宽又扁，渲染器不能按"摆在地上"的思路定位**：图鉴是把一块画布切成左右两格（每格约 424×81），高只有几十像素。鉴假员的器物如果沿用主画面的摆法（底足落在台面上、身体向上生长），到图鉴里整件器物就被顶到画布上方、整格空白。所以每个渲染器在 `GUIDE_FOCUS` 下都要有自己的构图：器物改成**整体缩小、按中心对齐**，同时把与信号无关的随机量在 `GUIDE_FOCUS` 下**定死**，保证左右两格只在"有没有信号"上不同。图鉴里唯一的差异必须是信号本身。
- **"砸碎"靠渲染器与引擎之间的一个单向开关**：碎片必须画在器物原来的位置和形状上，而只有渲染器知道器物长什么样、在哪儿。所以约定了一个模块级变量 `SMASH`：引擎在重绘每一帧之前把它设成 `{ t }`，渲染器看到它过了命中点（`SMASH_HIT`）就改画碎片，画完立刻清空。这样引擎不必知道器物的几何，渲染器也不必知道动画进度。另外碎片用**试次自己的 x 当随机种子**，所以逐帧重算却完全稳定——否则每一帧碎片都会重新乱飞一次。
